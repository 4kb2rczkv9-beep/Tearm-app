우리 집 생필품은 칫솔·수세미·샤워기 필터·아기 젖꼭지처럼 **"언제 바꿨는지 기억이 안 나는 것"** 투성이입니다. 이 문서는 그 문제를 푸는 앱의 1차 기획서(PRD)입니다. 코딩을 몰라도 읽을 수 있게 어려운 말은 풀어 썼고, 시간이 없으시면 **0장 요약 → 2장 MVP → 5장 기술 스택**만 보셔도 됩니다.

> 가칭 **「텀」** (교체까지 남은 '텀'을 세는 앱) · 작성일 2026-11-25 · 방향: **가족 공유 + 아이폰(iOS) 우선 출시**

## 0. 3줄 요약

- **무엇:** 집 생필품마다 교체 주기(또는 유효기간)를 정해 두면, 때가 되면 알림이 오고, 버튼 한 번으로 교체 완료·다음 날짜가 자동 예약되는 앱.
- **왜 가족:** 부부가 같은 목록을 보니 "내가 바꿨어?" 하는 중복도, 깜빡하고 아기 물건을 늦게 바꾸는 일도 줄어듭니다.
- **어떻게:** 1차 버전(MVP)은 위 기능만 제대로. 첫 화면 3개 → 가족 공유 → 알림 순서로 만들고, 도구는 **Expo(React Native) + Supabase**를 추천합니다. 1년차 최소 비용은 애플 개발자 계정 **129,000원**.

## 1. 앱 한 줄 정의 & 핵심 가치

**한 줄 정의:** 우리 집 생필품의 "바꿀 날"을 가족이 함께 기억해 주는 앱.

**해결하려는 문제 — 지금 집에서 실제로 벌어지는 일**

- 칫솔은 3개월, 수세미는 2~3주, 샤워기 필터는 3개월 — 주기가 제각각이라 머리로 다 못 외웁니다.
- 부부가 각자 바꾸다 보면 같은 걸 두 번 사거나, 둘 다 잊고 몇 달을 씁니다.
- 아기 젖꼭지·이유식 용품은 늦게 바꾸면 위생 문제로 바로 이어집니다.
- 정수기·가습기 필터처럼 "바꾼 날" 자체가 기억나지 않는 물건이 가장 위험합니다.

**핵심 가치 3가지**

1. **잊지 않게** — 물건마다 다른 주기를 앱이 대신 세어 주고, D-3·당일·지난 뒤에 알려 줍니다.
2. **한 번 누르면 끝** — '교체 완료'만 누르면 기록이 남고 다음 교체일이 자동으로 다시 잡힙니다. 입력은 등록할 때 한 번뿐.
3. **가족이 같은 목록** — 한 사람이 누르면 상대 폰에도 바로 반영되어, "나 바꿨어" 말할 필요가 없습니다.

**가족 공유가 핵심인 이유 (육아 가정 관점)**

뽀롱이 젖꼭지 주기를 2개월로 등록해 두면, 아침 9시에 혜원 님 폰으로 "뽀롱이 젖꼭지, 오늘 교체날이에요" 알림이 옵니다. 혜원 님이 교체하고 버튼을 누르면 남편 폰 목록에서 그 카드가 사라지고, 이력에는 "혜원 · 11/25 교체"가 남습니다. 남편은 굳이 확인하지 않아도 되고, 혜원 님은 "내가 했는데 또 사 왔네" 하는 일이 없어집니다. **육아용품은 한 사람만 관리하면 반드시 새는 항목이 생기기 때문에, 공유는 '있으면 좋은 기능'이 아니라 이 앱의 존재 이유입니다.**

**주 사용자**

- 1순위 — 30~40대 육아 가정(맞벌이든 한 명이 주 양육이든)
- 2순위 — 신혼·동거 커플, 부모님 댁 물건까지 챙기는 자녀
- 3순위 — 1인 가구(그룹은 1명도 허용해야 함)

**성공을 어떻게 볼지 (출시 후 3개월 지표)**

- 등록한 생필품이 5개 이상인 사용자 비율
- 알림을 받은 뒤 48시간 안에 '교체 완료'를 누른 비율
- 그룹 멤버가 2명 이상인 사용자 비율 (가족 공유가 실제로 쓰이는지)

## 3. 화면 구성도 (핵심 6개)

**전체 흐름**

`로그인 → 홈 ⇄ 생필품 상세 → 교체 완료` / `홈 → (+) 추가 → 추천 템플릿 또는 직접 입력` / `홈 → 가족 그룹, 설정`

### 3-1. 홈 — 오늘의 교체 리스트 (가장 중요)

- **상단:** 그룹 이름("우리 집")과 그룹 전환 아이콘 · 알림함(종) · 설정(톱니).
- **요약 카드:** "오늘 3개 · 이번 주 5개 · 지남 1개"를 큰 숫자로. 누르면 해당 항목만 걸러 봅니다.
- **필터 칩:** 전체 / 임박 / 지남 / 내 담당.
- **리스트 카드(한 줄에 하나):** 이름 · D-day("D-3", "오늘", "3일 지남") · 신호등 색 점 · 담당자 이름 · 마지막 교체일. 정렬은 **지난 것 → 오늘 → 가까운 순**.
- **카드 동작:** 탭하면 상세로 이동, 카드 안 '교체 완료' 버튼을 누르면 즉시 완료되고 3초 되돌리기가 뜹니다.
- **우하단 (+):** 추가 화면으로.
- **빈 화면:** "아직 등록한 생필품이 없어요" + [추천 목록에서 3개 추가] 버튼으로 첫 성공을 빠르게 경험시킵니다.

### 3-2. 생필품 추가

- **입력 항목:** 이름(필수, 30자) · 카테고리(욕실/주방/아기/뷰티/청소/기타) · 교체 주기(숫자 + 일/주/개월) · 마지막 교체일(기본 오늘) · 알림 시점(D-7/D-3/당일, 기본 D-3·당일) · 담당자(나/배우자/함께) · 메모.
- **자동 미리보기:** 입력하는 즉시 "다음 교체일: 2027-01-25 (D-62)"를 보여 줘 날짜 감각을 눈으로 확인.
- **버튼:** [저장]은 홈으로 돌아가 새 카드를 강조하고, [취소]는 입력을 버립니다. 저장에 실패하면 입력값을 남긴 채 "다시 저장"을 안내합니다.
- **검증:** 주기는 1일~3650일(10년)만 허용하고 이름은 비울 수 없습니다. 잘못된 값은 빨간 글씨 한 줄로 이유를 설명합니다.

### 3-3. 추천 템플릿 선택

- **구성:** 카테고리 탭(전체/욕실/주방/아기/뷰티/청소)과 항목 그리드. 항목마다 아이콘·이름·기본 주기를 표시합니다.
- **동작:** 여러 개를 탭해 선택(체크 표시)하고, 아래 고정 버튼 "선택한 5개 추가"를 누르면 한 번에 등록되어 홈으로 돌아갑니다. 주기는 기본값으로 채워지고 상세에서 수정할 수 있습니다.

### 3-4. 생필품 상세 · 교체 이력

- **상단:** 이름 · 큰 D-day 숫자 · 다음 교체일 · 주기 · 담당자 · 메모.
- **가장 큰 버튼 [교체 완료]:** 누르면 ① 이력에 오늘 날짜와 내 이름 추가 ② 다음 교체일 자동 재계산 ③ 가족에게 실시간 반영 ④ 화면 아래 3초 되돌리기.
- **이력 타임라인:** "혜원 · 2026-11-25 · 메모 없음" 식으로 최근 10건.
- **보조 버튼:** [수정](주기·담당자·알림 변경, 변경 전 확인 한 번) · [잠시 숨기기](삭제 대신 보관 — 이력은 남김).
- **삭제:** 화면 맨 아래 작은 글씨로. 두 번 확인 후 이력까지 지우며, 되돌릴 수 없다고 알립니다.

### 3-5. 가족 그룹

- **구성:** 그룹 이름 · 멤버 목록(이름과 역할) · 초대 코드 6자리(큰 글씨) · [코드 복사] · [링크로 공유](카카오톡·메시지) · [코드 재발급].
- **합류 화면:** 코드 6칸 입력 → "우리 집에 참여할까요?" 확인 → 참여. 틀린 코드는 "코드를 다시 확인해 주세요".
- **권한:** 만든 사람은 관리자(멤버 내보내기·그룹 삭제), 참여자는 멤버(생필품 추가와 교체).
- **나가기:** 내가 마지막 멤버라면 그룹과 데이터가 함께 정리된다고 안내합니다.

### 3-6. 설정 · 알림

- **알림:** 시간(기본 오전 9시, 07~22시 중 선택) · 종류 토글(D-7/D-3/당일/지남 리마인드) · 권한이 꺼져 있으면 "설정에서 켜기" 버튼.
- **계정:** 애플 로그인 상태 · 로그아웃 · 계정 삭제(앱 안에서 바로, 심사 필수) · 데이터 내보내기(CSV).
- **안내:** 개인정보처리방침 · 오픈소스 라이선스 · 버전.

**계산·알림 규칙 (앱 안에 넣을 규칙)**

- **다음 교체일** — 마지막 교체일 + 주기. '일/주'는 그대로 더하고 **'개월'은 달력 기준**으로 계산합니다(1월 31일 + 1개월 = 2월 28일). 화장품처럼 **개봉일 기준 유효기간**인 물건은 기준일을 개봉일로 저장해 같은 방식으로 계산합니다.
- **신호등** — 초록 D-8 이상 / 노랑 D-7~D-1 / 주황 오늘 / 빨강 지남.
- **알림** — 기본 오전 9시. D-3과 당일에 보내고, 지난 뒤에는 3일·7일째 한 번씩, 그 뒤로는 주 1회 최대 4회까지만(잔소리 방지). 담당자가 있으면 담당자에게 먼저, D+3까지 완료가 없으면 그룹 전체에 한 번 더.
- **가족 동기화** — 교체 완료 → 다음 교체일 갱신과 기록 저장 → 그룹 멤버 화면에 즉시 반영(실시간 구독) → 상대 폰에 걸려 있던 알림은 취소. 서버 푸시는 보내기 전에 최신 상태를 다시 확인해 이미 바뀐 물건은 건너뜁니다.
- **접근 권한** — "내가 속한 그룹의 데이터만 읽고 쓸 수 있다"는 규칙을 데이터베이스에 직접 겁니다(RLS). 남의 집 목록은 앱을 뜯어도 보이지 않습니다.
- **오프라인** — 인터넷이 없으면 마지막 목록을 읽기 전용으로 보여 주고, 연결되면 자동으로 최신화합니다.

## 5. 기술 스택 추천 (비개발자·1인 제작 기준)

### 결론 먼저

**Expo(React Native) + Supabase + Expo 알림**을 추천합니다. 이유는 세 가지입니다.

1. **한 번 만들면 아이폰과 안드로이드 둘 다** 나옵니다. 나중에 안드로이드를 포기하거나 처음부터 다시 만들 필요가 없습니다.
2. **비개발자에게 자료가 가장 많습니다.** 공식 문서·예제·영상이 풍부하고 AI 도움을 받을 때 오류 해결이 가장 잘 됩니다. 반면 Swift는 문법 오류 하나가 빌드 전체를 막는 일이 잦습니다.
3. **서버를 직접 만들지 않아도 됩니다.** 로그인·데이터베이스·실시간 동기화·예약 함수를 Supabase가 무료로 제공합니다.

- 참고 대안: **SwiftUI + 애플 CloudKit**은 아이폰만 할 거라면 서버 비용 0원에 가족 공유까지 되지만, 예약 알림과 통계 확장이 어렵습니다. "아이폰만, 진짜 최소로" 갈 때의 플랜 B입니다.

### 심사에서 걸리기 쉬운 것 (미리 피하기)

- **애플 로그인 필수** — 카카오·구글 로그인을 넣으면 사과 로그인도 함께 있어야 합니다(심사 지침 4.8). 이번엔 사과 로그인만으로 시작하면 안전합니다.
- **계정 삭제 제공** — 로그인 기능이 있으면 앱 안에서 계정 삭제가 가능해야 합니다(지침 5.1.1).
- **최소 기능** — 웹사이트를 감싼 수준이면 반려됩니다. 우리 앱은 알림과 가족 공유가 있어 통과 가능성이 높지만, 첫 화면이 비어 보이지 않게 템플릿을 꼭 넣습니다.
- **알림 권한 문구** — "교체일을 알려 드리기 위해 알림을 사용합니다"처럼 이유를 적습니다.
- **카카오 로그인은 V2로** — 개인도 카카오 로그인 자체는 쓸 수 있지만, 이메일 필수 동의 등은 비즈 앱 전환(사업자 정보 또는 개인 개발자 인증)이 필요합니다. 급하지 않으니 뒤로 미룹니다.

4. Supabase 프로젝트를 만들고 로그인 붙이기

### 어려운 말 풀이

- **PRD** — 만들기 전에 무엇을, 왜, 어떻게 만들지 정리한 기획서.
- **MVP** — 첫 출시에 꼭 필요한 기능만 모은 최소 버전.
- **D-day** — 교체일까지 남은 날. D-3은 "3일 남음".
- **푸시 알림** — 앱을 열지 않아도 폰에 뜨는 알림.
- **데이터베이스(DB)** — 앱의 데이터를 저장하는 표들의 모음.
- **실시간 구독** — 상대가 바꾸면 내 화면이 새로고침 없이 바뀌는 것.
